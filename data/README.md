# Data layout

The stable GitHub Release asset `aggregator.sqlite3` is the directly queryable public projection. `aggregator-full.sqlite3.zst` expands to the authoritative SQLite database generated by `scripts/collect.py`; it retains every full raw JSON payload and historical derived assessment.

`scripts/build_public_db.py` first verifies that the compressed full archive expands to the exact source-database SHA-256, copies the database, replaces only duplicated raw JSON columns with `{}`, applies the documented derived-history retention, removes the write-only metric deduplication index, vacuums, checks every retained table count and metric-history key, validates integrity, enforces a 95 MiB ceiling, and only then atomically publishes the public projection. Both assets use stable URLs configured in `../config/site.json`; scheduled refreshes overwrite those Release assets rather than adding large binaries to Git history.

The registration projection is `../index/records.jsonl`, with its normative field schema in `../index/schema.json`. SQLite table `index_records` mirrors that JSONL registry; it is rebuilt by `scripts/build_index.py` and must not be hand-edited.

The installable Market contract-v3 projection is mirrored byte-for-byte at `../index/market-registry.json`, `../docs/data/market-registry.json`, and `../plugin/data/market-registry.json`; the corresponding `market-registry.schema.json` files are mirrored the same way. `scripts/build_market_registry.py` derives plugins only from active, safe, source-declared Listings and joins active Plugin Packs to those exact plugin ids/specs. Invalid specs remain in full raw and SQLite history but cannot enter this projection.

`collection_runs` is the append-only dataset version log. Each run has a sortable `dataset_version`, UTC start/end dates, optional scheduled time, trigger, status, and import counters.

SQLite schema version 8 defines each item's `first_seen_at` and `last_seen_at` as the minimum and maximum dates of its linked observations. `first_seen_run_id` and `last_seen_run_id` identify runs with evidence at those dates. Schema initialization repairs older databases from `item_observations` without deleting history, and later out-of-order raw imports preserve the same boundaries. It also imports `../registry/packs.json` into `plugin_packs`, append-only `plugin_pack_versions`, and ordered `plugin_pack_members`; a repeated version must retain the same canonical definition SHA-256.

In the full archive, `raw_snapshots` stores the exact UTF-8 JSON file content in `payload_json`, plus its SHA-256, relative path, byte size, collection date, and run id. The public projection keeps those provenance fields but sets `payload_json`, redundant raw JSON columns including `upstream_entries.source_json`, and the column-redundant `fork_rankings.components_json` value to `{}`. `observations` links platform observations back to the raw snapshot in both forms.

The full archive retains every historical Fork snapshot, commit, changed-file record, Registry Listing observation, ranking, and value assessment. To remain directly downloadable and queryable, projection version 4 keeps each Fork's latest three commit records, the changed-file records from its latest evidence snapshot, its latest metadata snapshot plus any older snapshot referenced by retained evidence, the latest Fork ranking run, the latest observation per Registry Listing, and the latest complete value-assessment run. The projection removes `idx_metrics_dedupe` after explicit validation proves that `(item_id, observed_at, metric_source)` remains unique; the authoritative full database keeps the index for writes. `collection_runs` and normalized current records remain available in both databases. `public_projection_metadata.stripped_fields_json` records the retention rules, stripped fields, and dropped indexes.

`item_details` stores optional full-text enrichment from checked-in raw captures or permitted public endpoints. A successful detail row is idempotent on `item_id`; blocked, thin, and failed rows remain as provenance instead of being retried as new items.

`value_assessments` stores the versioned value matrix for every item in a collection run. Its six scores are utility, evidence, traction, ecosystem, freshness, and reviewability. `traction` is normalized within each platform; the matrix never adds stars, likes, views, and points across platforms. `risk_flags` and `confidence_score` expose missing evidence without turning unknown values into zero claims.

`raw/2026-08-15-egolite.json` is the first checked-in browser harvest. It records the query, source URL, collection method, visible result count, titles, authors, timestamps, media URLs, and platform-native interaction counters.

`raw/api/` contains checked-in timestamped GitHub/Hacker News API snapshots created by the scheduled refresh workflow. `raw/auto/` remains reserved for local API runs that should not be committed.

`raw/upstreams/` contains complete JSON snapshots from the configured community indexes in `config/sources.json`; their README/structured registry files, source-repository metadata, and normalized plugin references are preserved together.

Other dated raw files under `raw/` were already present in the workspace and are imported by a read-only legacy adapter. The adapter recognizes GitHub/HN API exports, X/XHS/Reddit/知乎 DOM captures, Bilibili metadata, WeChat articles, and open-web metadata without changing those files.

`raw/auto/` is reserved for local API snapshots and is ignored by Git because it can grow quickly. Keep any snapshot that supports a published claim by copying it into a dated, reviewed raw file. The public scheduled workflow writes reviewed snapshots under `raw/api/`.

Exact raw-file SHA duplicates are skipped at import. An item remains one row by canonical URL, while dated observation and metric rows preserve later changes in public content and counters.

Published `metrics` rows are append-only by canonical item URL, observation time, and metric source. Both scheduled publishers save the restored full database as a baseline and run `python3 scripts/validate_append_only.py --before <baseline.sqlite3> --after <candidate.sqlite3>` before committing generated files or uploading Release assets. The check also requires every preserved metric to retain the same collection run id and dataset version. For a confirmed historical regression, `scripts/repair_metric_history.py --baseline <previous-full.sqlite3> --database <current-full.sqlite3>` restores only baseline-present/currently-missing Listing metrics: values are replayed from the current full database's immutable raw payloads and must match every normalized baseline metric value, while run provenance comes from the previous authoritative database. The repair is atomic, idempotent, and refuses unsupported sources, mismatched values, or unresolved raw evidence.

`python3 scripts/reconcile_raw_snapshots.py --database <full.sqlite3>` imports checked-in non-Fork raw files whose exact SHA-256 is absent from an existing full database. It performs no network collection and creates a `collection_runs` row only when a missing raw file exists. The scheduled publishers call it after combining the completed collection database with the newest `main`, so reviewed browser evidence committed while a run is active cannot leave raw files outside `raw_snapshots`.

Every non-Fork `raw_snapshots.raw_path` is unique and must resolve to a checked-in file with the recorded SHA-256. If a historical collector reused and overwrote a path, run `python3 scripts/materialize_raw_snapshots.py` against the restored full database; it writes the preserved payload to a deterministic timestamp-and-hash path and updates only that snapshot's path. Fork API pages remain release-only payloads in the full archive because their expanded form exceeds normal Git repository limits; `--include-forks` is available for an explicit local restoration. The command refuses to repair from the stripped public projection.

`upstream_repositories` records monitored Registry Sources and community indexes. `upstream_entries` keeps each Listing identity, current active state, source-declared install/version/verification metadata, first/last collection run, raw snapshot id, and the de-duplicated `items` link when available. `upstream_registry_snapshots` records dated source format/count/status evidence, while `upstream_entry_observations` appends every successful Listing state, including deactivation after an authoritative missing-path observation. Failed or invalid source reads retain the last successful active state. Distinct monorepo install specs have distinct `listing_key` values; legacy logical duplicates remain inactive rather than being deleted.

`plugin_packs` records stable Pack identity, explicit active state, current version, maintainer, and first/last observation dates. `plugin_pack_versions` stores immutable bilingual task/description metadata, Pack dataset version/date, repository-relative source path, and canonical definition hash. `plugin_pack_members` stores each version's order, exact `deeplugin_id` and Install Spec, member name, required/alternative/complement relationship, group, and bilingual reason. Public Registry Pack members add current Listing/raw snapshot provenance while retaining `NULL` for unreported plugin versions. A missing current plugin id/spec does not remove the member; it sets `available=false`, records the id in `missingMembers`, and disables the Pack CTA.

`github_user_profiles` stores owner-deduplicated public GitHub account signals used by the Fork ranking: followers, public repositories, public gists, following, account creation/update dates, fetch status, and the exact API response in `raw_json`. `fork_rankings` keeps repository influence, reputation score, coverage, status, components, and the combined overall score in separate columns. `min_stars` in `config/forks.json` or `--min-stars` changes only the ranking pool; all observed Forks remain in the raw archive and historical Fork tables. `fork_snapshots.change_summary` is a deterministic one-sentence evidence summary based on compare results, changed-file categories, description, and README clues. The deep-scan queue prioritizes a bounded set of Forks pushed since their last audit without starving the never-scanned backfill; `docs/data/fork-catalog.json` publishes current coverage and the machine-readable queue projection.

The project stores external image/video/document URLs and thumbnails as metadata. It does not mirror platform media, bypass access controls, or infer missing engagement values. A missing metric is stored as `NULL`, not zero. Platform-specific counters such as favorites, shares, coins, danmaku, and Reddit upvote ratio stay in explicit SQLite columns plus the original metric JSON.
